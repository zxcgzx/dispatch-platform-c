## 3. 建模

14. **基础目标（★ 待确认）**：数据里没有发电成本，暂用“偏离当前方式最小”：min Σ_t Σ_g (P^G_{g,t} − P^{G,0}_g)²，P^{G,0}_g 取断面 PG。公式页和代码页都标“待确认”。真实成本函数由老师给定后替换。
15. **B3 的 Big-M**：代码里取 10 p.u. 仅作示意（只用于构建、不求解）；真实取值由求解链按支路定。
16. **B9（N−1）只作抽象块**：公式页只显示抽象形式并注明“展开形式由求解链定义”；代码里只记录事故集；规模估算里不计入约束数，试构建 T = 1 时跳过。
17. **规模估算口径**：变量 = v、θ（2·N·T）+ pg、qg（2·G·T）+ pf/qf/pr/qr（4·L·T）+ z（|L^s|·T，0-1）+ 开关动作 dz（|L^s|·T，连续，把 |z_t − z_{t−1}| 线性化）；约束 = B1、B2、B3（8·L·T）、B4（RATE_A>0）、B6（4·G·T）、B8、dz 线性化（2·|L^s|·T）+ 结构算子约束。B5 作变量边界、B7 不产生约束（z 直接取断面状态）。三种可开断集合口径下的开断变量数为 16000 / 3600 / 1712，与指令一致。
18. **dz 变量**：为了让“开关操作数”约束和惩罚项是线性的，引入 dz 连续变量。它是实现细节，不在指令的 B1–B9 公式里。
19. **试构建的安全边界**：在子进程里 `exec` 同一份 `model.py`，限时 60 秒。`custom_code` 先做静态检查（禁 import os/sys/subprocess…、禁 open/exec/eval/getattr 等、禁双下划线属性），不过即 E108/E402，不执行。★ 这**不是完整沙箱**：对来自不可信大模型的 `custom_code`，生产环境应再加容器 / 资源限制。
20. **算子库的 beta 缺省**：β 为空时用 `config/app.yaml` 的 `objective.beta_default`（0.1），并给 W110 警告；公式里保留符号 β，代码里用默认值。

## 5. 求解、指标、风险

30. **求解是黑盒**：mock 不生成任何开断方案或曲线（结果里这些字段为空）；导入时 `status = mock` 却带方案会被拒。没有任何求解加速 / 调参 / 热启动代码。
31. **外部命令（Windows）**：用 `shlex.split(posix=False)` 并去掉成对引号，避免路径反斜杠被当转义。
32. **N−1 直流筛查**：b = 1/(x·τ)（τ = TAP，0 按 1）；LODF 用对每个事故解一次线性方程（`splu`）得到。**LODF 用独立的“逐事故重解直流潮流”做了交叉验证**，含并联支路和变压器支路。
33. **事故前潮流用断面 PF（交流有功）作为基准**，再叠加直流 LODF 增量。这是筛查的常见做法，但基准与直流模型不严格自洽，所以卡片上明确写“非交流 N−1 校核”。限额取 RATE_A（MVA）当作 MW 限额，不做功率因数折算。
34. **孤岛事故统计**：事故集选“全部在运支路”时，775 条孤岛型事故不进 LODF，单列。累计净负荷把各次事故分别计入后加总，嵌套的孤岛会被重复计入，所以同时给出“单次最大”。
35. **调整后指标**：各时段取最坏值（负载率取每条支路时段最大，N−1 取最差时段）。结果里没有 `branch_flow` 时，负载率不显示（不拿断面潮流冒充）；mock 时全部显示“—”。
36. **本地风险规则**：ρ ≥ 100% 或 N−1 不通过 = 高；ρ ≥ 80% 或电压越限 = 中；否则低。**注意**：基态下 231 个母线 VM > VMAX（VMAX 统一 1.05，疑为默认值），所以断面本身的风险就是“中”。这是数据现状，不是程序错误。★ 课题 3 的口径定了之后替换。
37. **协商建议**：每条建议的数值留空，用户必须填写才能生成新版本（后端 400 拒绝空值）；N−1 反复越限的支路 → 建议断面限额；ρ ≥ 100% → 建议收紧 RATE_A；电压越限 → 建议收紧 VMAX。

## 7. 本轮升级补充的假设（单时段、内置求解、测点转换、地图）

43. **单断面 = 单时段**：时段数始终等于断面数。只有 1 个断面文件时按 1 个时段建模；多个断面按时刻排序组成窗口（最多 16 个，间隔 15 分钟）。之前“复制成 16 个时段”的做法已取消。单时段下“午后 / 明天”这类模糊时间说法不再追问；明确写出的时段（如“第 5 时段”）仍照常解析，超出范围由校验 E105 报错。
44. **内置求解器**：用 HiGHS（scipy.optimize.milp）求解**直流近似** OTS，不是交流 AC-OTS。目标是“偏离当前机组出力最小 + 开关动作惩罚”。直流模型不输出母线电压，也没有网损，所以 `loss_min`、`voltage_deviation` 两个目标算子在内置求解器里不起作用（求解结果里会说明）。需要交流求解时用 `SOLVER_MODE=external` 接现有求解链。
45. **网损与等值注入的处理**：断面总出力比总负荷多 679 MW（网损 105 MW，其余是平衡节点与等值机组的等值注入）。直流模型无损，所以把这部分按断面固定计入各节点平衡，使断面本身就是模型的可行点——小改动只引起小调整，而不是一次几百 MW 的虚假再调度。
46. **断面里本身越界的机组**（PG 不在 [PMIN, PMAX]）：用户没改它的上下限时，把当前出力纳入可行域以免无谓无解；用户用 Δπ 改了上下限的，严格按用户设定。
47. **推断项的确认**：用户在对话里亲自回答了方向和幅度（如“降低 20%”），即视为确认；在规格表里手填幅度则仍要勾选“我已确认”。
48. **演示场景**：L875 是 500kV 变压器支路，在网状部分，断面负载率约 30%。把它的限额压到很低（降低 92%）才会触发求解器的开断选择，所以演示场景用了这个幅度。场景里的幅度是演示用的，不是规程值。
49. **测点转换范围**：只做模拟测点（节点 → 测点、逆向恢复、回写）。变压器档位在节点模型里没有，记为 -999999（无值）。支路停运回写默认映射为两端虚拟开关同时断开——一条支路停运可由单端或两端断开实现，不能唯一反推，需结合现场规程确认。真实测点需要课题 2 提供映射、单位字典、标识范围。
50. **地图**：底图是大理白族自治州真实行政区划（DataV 公开的 GeoJSON，已内置到 `frontend/public/geo/dali.json`，运行时不联网）。数据里没有变电站经纬度，所以节点位置是按拓扑分区落在各县范围内的示意位置，不是真实站址；全部 905 个节点都在州界内（有测试校验）。有真实经纬度后替换 `data/cache/geo_positions.json` 即可。
51. **品牌**：页头放北京大学、中国南方电网、怀柔实验室三家 Logo，由 `三家Logo.png` 裁切并去白底得到（`frontend/src/assets/logo_*.png`）。
52. **界面措辞**：界面里不再放“证据性说明”类文字；动态建模与去幻觉方法统一称“动态建模与去幻觉方法”。
